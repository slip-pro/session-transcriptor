# C-12: Письма на порту 587 только с шифрованием
Status: agreed
Agreed: 2026-11-19 — «Да, сделай»
Request: правка из разговора после C-11: при отправке через Zoho на порту 587 код обязательно требует шифрование (STARTTLS), иначе пароль приложения от alexandra@kiberry.ai может уйти открытым текстом.
Why: чтобы пароль почтового ящика жены никогда не передавался без шифрования, даже если кто-то вмешается в соединение между сервером и Zoho. Сработало, если письма по-прежнему уходят, а без шифрования отправка отказывает.
Would fail if: письма перестают уходить через Zoho на 587; при отказе шифрования пароль всё же отправляется.
Size: small change — одна настройка отправки и тест; поведение для пользователя не меняется.
Today: при SMTP_SECURE=false (порт 587, так настроен сервер) шифрование включается, только если сервер его предложил; если предложение срезано — вход в ящик идёт открытым текстом.
After: при SMTP_SECURE=false отправка требует STARTTLS; без него письмо не отправляется, пароль не передаётся, в журнале MAIL_SEND_FAILED.
Won't do: смену порта или почтового сервиса; изменения писем и регистрации.
Must stay true: S-paid-2, S-paid-4 (письма подтверждения и сброса уходят); отправка в фоне и журнал без адресов (C-11).
Decided for you: nodemailer `requireTLS: true` при SMTP_SECURE=false; тестовый SMTP-сервер в тесте умеет STARTTLS с временным самоподписанным сертификатом (openssl), без openssl тест пропускается с причиной.

Scenarios:
- add S-paid-10: при отправке на порт 587 письмо уходит только после включения шифрования; сервер без шифрования не получает ни пароля, ни письма — test: .local/web/tests/c11-accounts.test.ts › smtp requires TLS
