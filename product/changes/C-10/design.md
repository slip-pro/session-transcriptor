# C-10 design: кабинет готов к выпуску (без выкладки)

## Map

All code lives in `.local/web` — its own git repo (branch `codex/linux-hosting`, remote `slip-pro/session-transcriptor`). Cabinet work is uncommitted there (`git status`: `app/cabinet/`, `app/api/cabinet/`, `lib/cabinet/`, scripts, tests untracked; `lib/jobs.ts`, `lib/pipeline.ts`, `scripts/worker.ts`, `package.json`, `app/layout.tsx`, `app/page.tsx`, `app/globals.css`, `lib/document.ts`, `next.config.ts`, `AGENTS.md`, `.gitignore` modified).

- **Server today** (read in code): `deploy/Dockerfile` (build stage runs `npm test && npm run lint && npm run build`; runtime copies standalone, `lib`, `scripts`, `node_modules`; `DATA_DIR=/data CODEX_HOME=/codex`), `deploy/compose.yaml` (web + worker, both mount `/opt/session-transcriptor/data:/data`, worker also `/codex`; read-only FS; env files `secrets/access.env`, `secrets/worker.env`; hardcoded `/opt/...` paths, two different image tags), `deploy/nginx.conf` (every app path behind `auth_request /_access_check` = old shared password; 401 → maintenance page), `deploy/README.md` (build, runtime config, rollback). `.dockerignore` excludes `.env*`, `.local`, `data`, `experiments`.
- **Cabinet storage** (read): `lib/cabinet/store.ts` `cabinetPath()` = `CABINET_DATA_DIR` or `$DATA_DIR/cabinet`; DB `cabinet.sqlite` (WAL). Audio files `cabinet/audio/<sessionId>/<storageId>.bin` (`lib/cabinet/audio.ts`). Word is generated on download from the DB (`app/api/cabinet/sessions/[id]/download/route.ts`) — no stored .docx. So in production the cabinet already lands in the persistent `/data` mount; nothing there is backed up.
- **Writers of `/data`** (read): `lib/jobs.ts` `cleanupExpired`/`recoverAndClean` iterate `allJobs()` = dirs whose `state.json` parses, under `jobDir` UUID regex → never touch `/data/cabinet`, `worker.json`, `deepgram-credit-alert.json`. `scripts/worker.ts` calls `syncAllProcessing`/`purgeOrphanedJobs` (`lib/cabinet/processing.ts`) — touch only job dirs with `job.cabinet`. Web and worker both open the same SQLite (busy_timeout 5000). Overlap with the new audio sweep and backup: safe (different files; SQLite handles concurrent writers).
- **Accounts** (read): `scripts/cabinet-user.ts` already creates an account (TTY prompt or JSON on stdin) and resets passwords; `lib/cabinet/auth.ts` has `disableSignUp` unless `allowSignUp`; env `CABINET_AUTH_SECRET` (≥32), `CABINET_URL` (https or localhost). Script appends a secret to `.env.local` if missing — on the server the env var is set, so the read-only FS is never written.
- **Processing** (read): `lib/pipeline.ts` `processJob` → ffmpeg to `audio.wav` (pcm_s16le 16 kHz mono) → `recognizeAudio` → `lib/deepgram.ts` `transcribeAudio(wav,…)` posts `Content-Type: audio/wav` → `raw.json` → deletes `wav`/`input.audio` → `lib/formatting.ts` `formatChunk` runs `codex exec …` → DOCX. `ProcessError` codes. Health: `app/api/health/route.ts` reports only the worker lease.
- **Audio UI** (read): `app/cabinet/ui/audio.tsx` shows the player when `value` is set, else «Прикрепить запись»; the details text says «Прикреплённая запись хранится до удаления» — false after this change. `session-workspace.tsx` gates timecodes/previews on `item.audio`.
- **Old site page** (read): uncommitted edits in `app/page.tsx` (link «Кабинет коуча», «Открыть кабинет» block, options folded into `<details>`, new background) and `app/globals.css` (body font). They would change transcribe.kiberry.ai on next deploy, which the brief forbids. `app/layout.tsx` (local Manrope as `--font-geist-sans`) is needed by the cabinet (`room.css`) and does not change the old page (its body font comes from `globals.css`).
- **Build facts**: Node 24.22.1 path for local tests (product/operations.md C-3/C-5 notes); `npm test` = `node --import tsx --test tests/*.test.ts`; browser tests are plain `.cjs` with bundled Playwright + installed Chrome (pattern: `tests/cabinet-c8-home.cjs`). Docker 29.8.2 available locally. Local ffmpeg (winget) has `libopus`; base image is Debian bookworm ffmpeg (has libopus — verify in docker test). Live audio: `auido/GMT20260723-110224_Recording.m4a` (root). Deepgram key: root `.env` (never print). Local Codex login: default `~/.codex` of this computer (never copy its `auth.json` anywhere — copying is what broke the server on 2026-11-11).

## Options

1. **Leave as is + docs only.** Fails the brief: no backup, no retention, WAV upload, no Codex check, lint breaks the image build.
2. **Minimal additions inside the existing two containers (chosen).** Worker gains three periodic duties (audio expiry, daily backup, Codex probe); nginx gains public cabinet locations; compose gets a backups mount and path variables; deploy README gets the release/rollback procedure. No new services, no new dependencies.
3. **Host cron/systemd for backup and expiry** (like `transcriber-credit-alert.timer`). More moving parts on the host, not testable in the local Docker run, and the worker already has the store and a cleanup loop.

## Decision

Option 2: everything testable locally in Docker with the same image, nothing new to install on the server besides a directory and nginx locations; undo = previous image tag + previous nginx file.

## Program design

- `lib/deepgram.ts`: `transcribeAudio(file: string, duration, language, fetcher)` — unchanged signature; sends the file's own type: `Content-Type: audio/ogg` for `.ogg`. `lib/pipeline.ts`: ffmpeg output `audio.ogg` with `-c:a libopus -b:a 48k -ac 1 -ar 16000 -application voip` (replaces `pcm_s16le` + `audio.wav`); cleanup removes `audio.ogg` (and a stale `audio.wav` if present). Export `ENCODE_ARGS` for the test. 48 kbps Opus ≈ 5× smaller than 16 kHz WAV (256 kbps).
- `lib/codex-health.ts` (new): `probeCodex(runner = run): Promise<CodexHealth>` runs `codex exec --skip-git-repo-check --sandbox read-only --disable shell_tool --ephemeral -` with input "Reply with OK", timeout 120 s; `type CodexHealth = { state: "ok" | "failed"; checkedAt: number }`; `writeCodexHealth(h)` → `$DATA_DIR/codex-health.json` (atomicWrite); `readCodexHealth(): CodexHealth | null`. `app/api/health/route.ts`: `{status, worker, codex: {state, checkedAt} | null}`; HTTP 503 when the worker lease is stale **or** `codex.state === "failed"`; `status` = `"ok" | "worker_unavailable" | "codex_login_failed"`.
- Retention: `cabinet_audio` gains column `expired_at TEXT` (added like `meeting_minutes`). `CabinetStore.expireAudio(before: string): {sessionId, storageId}[]` selects rows `uploaded_at < before AND expired_at IS NULL`; `markAudioExpired(sessionId, at)`. `lib/cabinet/audio.ts` `expireOldAudio(store, now = Date.now(), days = 30)`: for each row delete the file, then mark expired. `audioMetadata()` returns `null` for expired rows; `CabinetSession` gains `audioExpiredAt: string | null`. `audioFile()` throws `AUDIO_UNAVAILABLE` for expired rows (so playback, retry copy and `previousAudio` behave as "no audio"). `setAudio` resets `expired_at=NULL`, so re-attaching a recording after expiry works and starts a new 30 days. `AUDIO_RETENTION_DAYS = 30` exported. User deletion via `deleteAudio` unchanged.
- Audio UI (`audio.tsx`): new optional prop `expiredAt`; when `value` is null and `expiredAt` is set, show the line «Запись удалена через 30 дней после загрузки. Прослушивание недоступно, текст и заметки сохранены.» above the existing «Прикрепить запись» button (button stays). Details text becomes «Запись хранится 30 дней после загрузки, потом удаляется автоматически. Транскрипт, закладки и выжимка останутся.» `session-workspace.tsx` passes `expiredAt={item.audioExpiredAt}`. No other UI change.
- Backup: `lib/cabinet/backup.ts` (new): `backupCabinet(store, dir, now = new Date(), keep = 14): Promise<string | null>` — if `cabinet-YYYY-MM-DD.sqlite` (UTC date) exists return null; else `VACUUM INTO '<dir>/.tmp-<uuid>'`, `PRAGMA integrity_check` on the copy, chmod 0600, rename; delete oldest beyond `keep`. Worker runs it when `CABINET_BACKUP_DIR` is set (skips otherwise).
- Worker duties (`scripts/worker.ts`): the 60 s tick runs three independent steps, each with its own `try/catch` and log code, so one failing duty never stops the others: (1) existing `syncAllProcessing().then(cleanupExpired)` (`CLEANUP_FAILED`), (2) `expireOldAudio` (`AUDIO_EXPIRY_FAILED`), (3) `backupCabinet` (`BACKUP_FAILED`). The Codex probe is not on a timer: it runs at start and in the main loop's idle branch (no queued job) when the last check is older than 60 min, so it never runs alongside a job's Codex call; a job whose formatting succeeded refreshes `codex-health.json` as ok (no extra probe). Includes DB only (clients, meetings, transcripts, notes, accounts → Word regenerable); audio excluded by construction.
- `scripts/cabinet-restore.ts <file>` (new): refuses if `worker.json` lease is fresh, with the message «Останови web и worker и подожди 90 секунд» (`compose stop` doesn't run the worker's `finally`, so the lease looks fresh for up to 90 s); checks `integrity_check` = ok and that table `cabinet_sessions` exists; moves current `cabinet.sqlite`, `-wal`, `-shm` to `cabinet.sqlite.before-restore-<ts>*`; copies backup to `cabinet.sqlite` (0600).
- Deploy: `deploy/compose.yaml` — `${ST_ROOT:-/opt/session-transcriptor}` (with the default, every time) for host paths, `${ST_IMAGE:-session-transcriptor:20261111-cabinet}` for both services, `${ST_NAME:-session-transcriptor}` container prefix, `${ST_WEB_PORT:-4025}`; worker mounts `${ST_ROOT}/backups:/backups`, env `CABINET_BACKUP_DIR=/backups`. Web env file gains `CABINET_AUTH_SECRET`, `CABINET_URL=https://transcribe.kiberry.ai`. `deploy/nginx.conf` — before `location /`: `^~ /_next/static/` and `= /cabinet-room.svg` (public static), `^~ /cabinet` (page, no auth_request, `private, no-store`, noindex), `^~ /api/cabinet/` (no auth_request; `proxy_request_buffering off`, `proxy_http_version 1.1`, timeouts 1900 s), `= /api/cabinet/recordings` (+ `limit_conn transcriber_upload_ip 1`, `transcriber_upload_global 3`, submit/global rate zones), `= /api/cabinet/auth/sign-in/email` (+ `transcriber_login` zone). Every cabinet location sets `Host`, `X-Forwarded-Proto`, `X-Forwarded-For $remote_addr` (better-auth's per-IP sign-in limit needs it); any location that adds its own `add_header` repeats the server-level `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` (nginx doesn't inherit them). `deploy/cabinet-user.sh`: `docker exec -it` when stdin is a terminal (`[ -t 0 ]`, hidden password prompt), else `-i` (JSON on stdin) — `${ST_NAME:-session-transcriptor}-web node node_modules/tsx/dist/cli.mjs scripts/cabinet-user.ts "$@"`. `eslint.config.mjs` ignores `tests/**/*.cjs`, `.local/**`.
- `deploy/README.md` — new section «Кабинет: выпуск и откат» (commands only, not run): directories + ownership (`backups` 0700 uid 1000), env additions, `codex login --device-auth` with `CODEX_HOME=/opt/session-transcriptor/codex` run in the worker image (server's own login, never a copied auth.json), image build/tag, keep previous tag, `nginx -t` + reload, account creation, health check, restore procedure, rollback (both previous tags — web `20261104-deepgram`, worker `20261104-credit-alerts` — + previous nginx file; cabinet data stays, old images ignore it); after the first day check that `backups/cabinet-<today>.sqlite` exists.

## Risks

- Opus changes recognition: guarded by the 180 s WAV-vs-Opus comparison; fallback = FLAC (lossless, ~2× smaller) — switch is one ffmpeg arg set.
- Codex probe consumes subscription quota: 24 tiny calls/day; acceptable. A probe can fail for a network blip → health 503 until the next probe (≤ 60 min); harmless.
- Public `/_next/static/` exposes old-site JS bundles (no secrets, no data). Cabinet APIs stay behind cabinet sign-in; isolation tested.
- Base image Node too old for `node:sqlite` features → image build fails in tests; handled by bumping the base digest.
- Backup on the same disk: disk loss loses both (accepted in brief; off-server copy later).
- Restore overwrites the live DB: script keeps the previous DB as `before-restore-*` and refuses while the worker runs.
- Brief's "Would fail if": data loss on restart (persist test), cross-coach leak (isolation test), mock-only path (live run), old site broken (old-site test + page files restored from HEAD).

## Decisions to keep

- Deepgram receives Ogg/Opus 48 kbps mono 16 kHz instead of WAV — 5× less upload; replaces pcm_s16le WAV.
- Codex login health is probed hourly by the worker and exposed in `/api/health`; replaces lease-only health.
- Cabinet audio lives 30 days from upload, then the file is deleted and the meeting keeps text; replaces "kept until deleted".
- Daily DB-only backup by the worker into `/backups`, 14 kept, restore via `scripts/cabinet-restore.ts`.
- Cabinet routes bypass the old shared password in nginx; the old site keeps it.
