# C-10: Кабинет готов к выпуску (без выкладки)
Status: agreed
Agreed: 2026-11-11 — «Да, как советуешь»
Deferred: 2026-11-11 — «погоди, только не надо сейчас бежать и делать. запиши в план». Дизайн и сборку не начинать, пока владелец не скажет.
Request: «давай готовить кабинет к выпуску. но пока не выкладывать» (2026-11-11)
Why: чтобы в любой момент можно было одной командой выложить кабинет и дать паре человек пользоваться им на своих записях. Главная проверка: настоящая запись, загруженная через кабинет, превращается в Word в формате ICF.
Would fail if: кабинет на сервере теряет клиентов, записи или Word после перезапуска; один тестировщик видит записи другого; основной путь «аудио → Word» работает только на подставных ответах; старый сайт transcribe.kiberry.ai ломается или меняется.
Size: feature — серверное хранение личных данных третьих лиц (сессии клиентов), личные аккаунты, внешние сервисы Deepgram и OpenAI/Codex, резервные копии.
Today: кабинет существует только на этом компьютере и не сохранён в git. Настоящую запись целиком он ни разу не обработал: ключа Deepgram в его окружении не было, тесты подставляют ответы. Серверная сборка содержит только старый сайт, а при сборке образа запускается lint, на котором сейчас 49 ошибок в тестовых скриптах кабинета. У базы кабинета нет постоянного места на сервере и резервных копий. Аккаунты заводятся скриптом вручную. Вход Codex на сервере был копией с компьютера и протух 2026-11-11. Записи уходят в Deepgram несжатым WAV.
After:
- Одна настоящая запись прошла через кабинет локально: загрузка → распознавание Deepgram → пунктуация Codex → Word, который открывается и соответствует формату ICF.
- Код кабинета сохранён в git проекта веб-приложения (локальные коммиты; отправка на GitHub — только по отдельному «да»).
- Серверная сборка включает кабинет и обработчик: база, записи и результаты лежат в постоянном каталоге и переживают перезапуск и пересборку. Сборка проверена локально в Docker, проверки сборки проходят.
- Готов порядок выкладки и отката: настройки nginx, переменные окружения, команды. Всё описано, но на сервере не применено.
- Вход в кабинет: у каждого тестировщика свои почта и пароль. Общего пароля «Для своих» поверх кабинета нет, этот пароль остаётся у старого сайта. Аккаунт заводится одной командой; самостоятельной регистрации нет.
- Хранение: аудио хранится 30 дней с загрузки, потом удаляется автоматически. Расшифровки, заметки и Word остаются, пока коуч сам не удалит встречу. После удаления аудио встреча открывается, а прослушивание показано недоступным.
- Ежедневная резервная копия базы, расшифровок и Word (без аудио) с проверенным восстановлением.
- У сервера свой вход Codex, а не копия с компьютера владельца. Протухший вход виден в проверке здоровья сразу, а не по упавшему заданию. Инцидент 2026-11-11: копия входа с 4 ноября протухла, все задания падали на пунктуации; владелец заново вошёл через device-auth.
- В Deepgram уходит сжатый файл, а не WAV, который втрое больше. 2026-11-11 запись на 23,5 МБ превратилась в WAV на 77 МБ, и отправка шла около 7 минут со скоростью ~180 КБ/с; 4 ноября 27-минутная запись проходила за 7 секунд.
Won't do: выкладка на сервер и любые изменения на transcribe.kiberry.ai; отправка кода на GitHub без отдельного «да»; оплата, квоты и бесплатные 3 расшифровки; самостоятельная регистрация; приглашения по почте; изменения интерфейса кабинета.
Must stay true: старый сайт и его общий пароль работают как сейчас; записи каждого коуча видны только ему; аудио уходит только в Deepgram, текст только в Codex/OpenAI — новых получателей нет; ключи и пароли не попадают в git и в образ.
Decided for you:
- Резервные копии лежат на том же сервере в отдельном закрытом каталоге; копию вне сервера можно добавить позже.
- Настоящая проверка: запись от 23 июля (`GMT20260723-110224`), уже лежащая на этом компьютере, через ключ Deepgram из корневого .env и вход Codex этого компьютера. Около $0.20 за распознавание.
- Пилот рассчитан на пару человек: один обработчик и очередь по одной записи, как на старом сайте.
- Тестовые .cjs-скрипты исключаются из lint, чтобы сборка образа проходила (пункт из очереди).
- Сжатая отправка и проверка входа Codex меняют общую обработку, поэтому старый сайт получит их только при следующей выкладке, которую решает владелец.
