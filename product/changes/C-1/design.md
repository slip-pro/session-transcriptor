# C-1: Подход

## Approach

- В `.local/web/app/cabinet/ui/workspace.tsx` общий picker и dropzone определяют аудио/JSON; отдельный импорт в «Других способах» убирается. JSON передаётся выбранным файлом в существующий SessionForm; встреча без записи остаётся рядом со входом.
- Классификацию размера/расширения вынести в маленькую чистую функцию `lib/cabinet/materials.ts`, общую для picker и dropzone. JSON до 8 МБ, аудио до 500 МБ, неподдерживаемое расширение — ясная ошибка. Повторная загрузка прерванного аудио принимает только аудио.
- В `forms.tsx` принять initialFile: показать имя и короткие параметры импорта, убрать повторный выбор материалов/файла. Сохранение использует прежний POST sessions; новый ASR не запускается.
- `preparation.tsx` по «Изменить заметку» загружает исходную сессию и использует общий SessionEditor/useSessionEditor с ownerId. Черновики, автосохранение и выбор конфликтов переиспользуются. При редактировании подготовка не размонтируется от обновления истории; локальные изменения не заменяют источник отдельной сущностью.
- В `session-workspace.tsx` связанный клиент показан текстом; «Изменить привязку» раскрывает ClientPicker без создания. Создание остаётся только для ещё не связанной сессии/загрузки. Повторные клики не переименовывают клиента или подписи DOCX.
- Визуальная база: существующие `room.css`, кнопки/формы, кремовый фон и сливовый акцент. На телефоне поля/действия без горизонтального переполнения; редактор заметки раскрывается в том же блоке.
- До кода воспроизвести три лишних перехода на безопасном учебном клиенте. Сначала тест маршрутизации файлов на старом коде; затем узкие тесты редактора/импорта и проверка браузером: JSON с главной, заметка на месте после reload, отсутствие создания у связанной сессии.
- Локальный preview — localhost:3100; реальные внешние сервисы и пользовательские записи не использовать. Окончательные проверки и сохранение продуктовой памяти — после показа и ответа Сергея.
