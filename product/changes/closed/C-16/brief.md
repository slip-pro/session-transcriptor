# C-16: Войти через Google
Status: agreed
Agreed: 2026-11-19 — "Да, как советуешь"
Request: «делаем дальше по плану - авторизацию через гугл» (2026-11-19); ранее, C-13: «давай может сделаем авторизацию через гугл? она всё равно нужна»
Why: регистрация и вход без придумывания пароля и без ожидания письма — меньше людей отваливается между главной и первой записью. Работает, если человек с Google-почтой за пару нажатий оказывается в транскрибаторе со своими тремя бесплатными записями.
Would fail if: через Google можно попасть в чужой аккаунт или в кабинет без приглашения; появляются два аккаунта на одну почту и записи «теряются»; аккаунт создан без согласия на обработку данных.
Size: feature — вход, личные данные, внешний сервис (Google).
Today: вход и регистрация только почтой и паролем, с подтверждением письмом (C-11). Google используется только для подключения календаря в кабинете (C-13, свой модуль, D24).
After: на экранах регистрации и входа транскрибатора и на входе в кабинет есть кнопка «Войти через Google». Google спрашиваем только почту и имя — не календарь. Почта от Google считается подтверждённой.
Won't do: вход через других провайдеров; подключение календаря одной кнопкой со входом (остаётся отдельно, D24); отвязку Google от аккаунта и смену почты; проверку приложения Google (отдельный пункт очереди); оплату.
Must stay true: кабинет только по приглашению (D21) — Google-аккаунт без отметки видит «Кабинет пока открыт по приглашению»; согласие на обработку данных хранится датой для каждого нового аккаунта; бесплатные записи считаются на аккаунт (D22) — вход через Google в существующий аккаунт не даёт новых трёх; подключение календаря работает как раньше.
Decided for you:
- Вход через better-auth на том же OAuth-клиенте Google, что и календарь (D24); адрес возврата `/api/cabinet/auth/callback/google`; в тестах — поддельный Google, как в C-13.
- Разрешения только `openid email profile`; храним почту и имя, фото не храним.
- Почта Google принимается, только если Google сам отмечает её подтверждённой.
- Если почта совпала с аккаунтом, чья почта ещё не подтверждена, при связывании пароль этого аккаунта сбрасывается и все его сессии закрываются — так тот, кто зарегистрировал чужую почту, теряет доступ (закрывает и пункт очереди про чужую почту для этого пути).
- Владелец вписывает `/api/cabinet/auth/callback/google` (боевой адрес и localhost:3111) в OAuth-клиент; живая проверка — после этого.

Owner decisions (2026-11-19):
1. Почта Google совпала с уже зарегистрированным аккаунтом — связываем: человек входит в свой аккаунт со своими записями.
2. Согласие при первом входе через Google — после возврата от Google новый аккаунт видит один экран согласия с кнопкой «Продолжить»; без согласия аккаунт не создаётся.
