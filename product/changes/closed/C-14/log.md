# C-14 log: rulings and deviations

- Slice 1, tests/c13-schedule.test.ts: the exact key list of an event now includes `editable` and `recurring` (the design adds both fields). Only that list changed; no assertion weakened. Cost if wrong: none, the fields are in the design.
- Slice 1, `write()` is a separate function next to `api()` instead of extending `api(owner, path, init)`: reads keep their retry and stale-cache behaviour untouched, writes never repeat. Cost if wrong: none for behaviour; a little duplicated token handling.
- Slice 1, `NewMeeting.id` is required (400 when missing or not 26 chars of 0-9a-v), as the review (m2) asks the window to always send it. Cost if wrong: a client that omits it gets 400 instead of a Google-made id.
- Slice 1, the end time goes to Google as a UTC instant (`...Z`) with the same `timeZone`; the start is sent exactly as given (offset kept). Cost if wrong: none, both are valid RFC3339 with timeZone.
- Slice 1, review m3 second half (a 401 again after a fresh token gives `CALENDAR_SAVE_FAILED` and keeps the token) is implemented but not covered by a test: the fake cannot return 401 for a valid fresh token. Cost if wrong: a coach would be sent to reconnect in a rare case where she should retry.
- Slice 1, the calendar list (with `accessRole`) is cached up to CALENDAR_CACHE_SECONDS, so a role changed in Google shows after the cache expires; the server also re-reads the event itself before every write. Cost if wrong: one refused write instead of a hidden button.
- Slice 1, fake Google: `setEvents` has no `account` argument; calendar ids are unique per account (`other@gmail.test`), and tokens see only their account's calendars (`state.nextAccount`). Cost if wrong: none for tests; the preview server can still use it as before.
- Slice 2, the preview fake Google gets only the foreign meeting «Встреча у Ани» (Monday 14:00 of this week), not the read-only calendar `holidays@group.test` the design lists: a third calendar breaks the C-13 `connect` step (it expects exactly two). The read-only calendar stays covered by the server test `not own`. Cost if wrong: no browser check of a reader calendar.
- Slice 2, the fake gets test-only `POST /__flags`, `GET /__events`, `GET /__log` (no sign-in, fake tokens only) so the browser test can set failure flags and read what Google stored. Cost if wrong: none, it is a test helper.
- Slice 2, c14-edit.cjs makes its own meetings through the server route for move/cancel/layout (steps do not depend on each other) and removes what it made at the end; the whole file runs in one Playwright context with timezoneId Asia/Yekaterinburg. Cost if wrong: none.
- Slice 2, the default title is «Сессия с <полное имя клиента>» (the card's name as written). Cost if wrong: one string.
- Slice 2, `defaultStart`: today before 07:00 starts at 08:00, after 20:59 at 10:00 tomorrow, a future shown day at 10:00 (the design only names 08:00-21:00 / else 10:00 tomorrow). Cost if wrong: another prefilled time.
- Slice 2, a save error with a possibly lost answer (CALENDAR_SAVE_FAILED or network) reloads the schedule behind the open window, as the design's Risks says; the window keeps its fields and id. Cost if wrong: one extra GET.
- Slice 2, `CALENDAR_NOT_CONNECTED` in the window also shows «Переподключить» (design m3), not only `CALENDAR_NO_WRITE`. The duration select has aria-label «Длительность» because the label text would otherwise include all options. Cost if wrong: none.
- Slice 2, `NextMeeting` became `ClientMeetings` (same request, plus «Назначить встречу»), as the design asks. After a create from the client's page the message «Встреча создана» shows under the head. Cost if wrong: none.
- Slice 3, `dropTarget(startMin, deltaY, hourPx, day, minutes = 0)` has a fifth argument, the meeting's length, so the end can be kept within 24:00 (the design's four arguments cannot know it). Cost if wrong: one optional argument.
- Slice 3, the target column is found with `elementsFromPoint`, skipping the dragged block itself (it is a child of its home column and would always win). The block is moved with a CSS transform and leaves a dashed ghost at its old place; after a successful drop it stays shifted with `aria-busy` until the reloaded meeting arrives (10 s fallback so a lost reload cannot leave it floating). Cost if wrong: none.
- Slice 3, the click that follows a drag is swallowed (flag cleared on the next tick), so dropping never opens the meeting window; Escape during the drag also ends in no window. Cost if wrong: none.
- Slice 3, the guest confirmation «Перенести?» lives in `ScheduleView` (one window, answer through a promise); the block stays at the dropped place with `aria-busy` while it is open and returns on «Не переносить» or Escape. Cost if wrong: none.
- Slice 3, `drag` step: the phone check uses a second Playwright context (touch, 390 px, same sign-in via storageState) with a real tap, plus a synthetic touch pointer sequence to prove the pointerType gate; real touch swipes are not emulated. Cost if wrong: the swipe path is covered only by the synthetic events.
- Slice 3, the `drag` step scrolls the block to the viewport centre before dragging, so the 2 h target is on screen. Cost if wrong: none.
- Окно «Новая встреча» со страницы клиента показывает клиента без выбора и без «+ Новый клиент» (владелец на показе: «зачем тут кнопка + новый клиент?»); из расписания выбор остаётся. Цена ошибки: из карточки нельзя сменить клиента — открыть из расписания.
- Fixes after the showing: the «Все встречи» button «Добавить запись» is hidden while there are no records at all (the empty card has the same button), like «+ Запись» on a client. Cost if wrong: one more button when empty.
- Fixes after the showing: a retried create on the 409 path PATCHes only when title, start/end or the guest differ; the guest is compared by the requested address (present or not), and with no invite any existing non-self guest is removed. - Fixes after the showing: the move form's own test line «minutes 3 is refused» became «minutes 0, 1441 and 7.5 are refused» because a 3-minute move is now valid (any whole 1-1440). The time field step is 60 s for a move and stays 900 s for a new meeting. Cost if wrong: none.
