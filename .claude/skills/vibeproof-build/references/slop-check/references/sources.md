# Sources and adaptation notes

Reviewed 2026-10-12. This is a synthesis for the existing slop-check workflow, not a verbatim bundle of upstream instructions. Links document provenance, not automatic updates or permissions to run upstream code.

- [blader/humanizer](https://github.com/blader/humanizer), SKILL.md v3.1.0: structural patterns, writer/reader context, second-pass review and source-fact preservation. We do not adopt blanket dash removal or permission to invent personal reactions.
- [andreaskonopka/humanizer](https://github.com/andreaskonopka/humanizer), skills/humanizer: structure before vocabulary, language-specific conventions, preservation of uncertainty and limits on unsupported detail. We do not remove or rewrite citations automatically.
- [hardikpandya/stop-slop](https://github.com/hardikpandya/stop-slop): concrete editing checks and five qualitative dimensions. We reject blanket bans on adverbs, passive voice, inanimate subjects, questions and three-item lists; the existing slop-check score remains the single optional scale.
- [sho-das/clear-english](https://github.com/sho-das/clear-english): familiar words, audience-aware explanations and precise meaning. We do not import a fixed story template, require one idea per sentence mechanically, or add example facts.
- Existing slop-check: Russian marker catalogue, audit/edit/targeted modes, genre calibration, protected voice, glossary integration and paragraph-based scoring. The shared workflow now limits over-editing in both languages.

English collocations, dialect handling and offering-consistency checks were added for editing practical business prose. Project-specific style comes from the active project rather than becoming a global English rule.
