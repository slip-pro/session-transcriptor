# Pause, resume and switching

**Resume.** Read the open change's brief, log and report, `git status` and `git log`, and the recent
chat: saved files can't hold messages that were never saved. Compare what the files say with what is
on disk and what a safe observation shows; keep both if they differ and don't invent what happened
in between. Reuse the agreement and continue from the next unfinished step: no new intake, no repeated
interview. Ask again only if new evidence changes a consequential choice. Restart a preview yourself
and check that earlier evidence still matches the code.

**Investigations that may resume** keep in the log: the current hypothesis, causes ruled out and why,
what is still uncertain and the next check that would decide it. Never repeat a disproved fix
without new evidence.

**Pause.** Commit or describe the work in progress without resetting anyone's edits. Pausing doesn't
undo, close or delete anything. Write the next step in the log. If something partial is already live,
say what that means for users.

**Cancel.** Stopping work that is already built needs a scoped reversal through the normal route;
never claim code is gone because the change was marked cancelled.

**Switch.** Keep unfinished feedback and the next step in the log. Don't slip the new request into
the agreed brief. Say if open work blocks publishing.

**Earlier work, unknown acceptance.** If you can't tell whether a shown result was accepted, ask once.
